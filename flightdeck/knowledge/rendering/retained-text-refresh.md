# 缓存文字的刷新与恢复

对保存字符串或排版缓存的控件，修改字符串成功不等于画面已经改变。验证时同时检查原始值、实际显示和停止后的恢复；每秒观测计数也不能作为刷新成功证据。

## 实施顺序

1. 从 RTTI、导出或框架命令关系识别完整正文与对象归属，分别核对版本、编码及调用约定。
2. 控制线程只发布字典代次和刷新请求；由目标对象所属线程执行引擎 setter，以及经过验证的显示缓存重建。不能用推进剧情替代当前句刷新。
3. 保存原文和最后写入值。外部写入优先，追加前恢复原文，销毁时删除记录；停止时仅在类型、线程及最后写入值仍匹配时恢复。无回调导致恢复超时，应报告失败并保留待恢复状态。
4. 将已确认的控制前缀、正文和结束标记分开。按实际代码页严格往返转换；未知控制命令或无法编码的译文透传，不能固定截取前缀长度。
5. 先用独立显示缓存的合成宿主锁定“只改缓冲但画面不变”的红例，再验证首代、次代、相同译文重试及停止可见恢复。

## 验证边界

CatSystem2 UTF-8 正文与历史行使用不同显示入口；经典 ANSI 分支又有不同的对象布局、寄存器参数和结束标记。某条路径通过不能推广为所有版本或历史页通过。经典分支的颜色前缀和代码页处理属于该 profile，不是所有引擎通用的文本清洗规则。
