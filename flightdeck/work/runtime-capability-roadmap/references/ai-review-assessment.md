# AI 评审路由：能力升级

## 吸收为 Roadmap

- 多进程软件的 Process Family 与子进程生命周期。
- 一个写入所有者、多个观察订阅者共享 Target Runtime 的执行模型。
- DirectWrite、UI Automation 和受控 OCR；其他图形 API 按证据逐项评估。
- Adapter Watchdog、熔断、SEH/VEH 与字体度量/布局能力的专项研究。
- 有界 Observation Evidence 和 major-state diagnostic journal。
- 字典级可选 Match Policy，但默认精确并要求编译期碰撞诊断。

## 仅采纳问题，不采纳原解法

- 分裂 text run 是 Adapter 观察重组问题，不采用全局 substring fallback。
- 图标字体误伤需要字体保护策略，不采用不可解释的永久硬编码黑名单。
- 丰富运行证据属于可选 envelope，不扩张核心 `TextObservation` ABI。
- 模块数量可能影响构建，但只有通过 Interface 深度与删除测试后才能调整 crate seam。

## 不进入 Roadmap

- Dictionary Entry 携带 Context、窗口、坐标、字体、hash 或 Probe Metadata。
- Runtime fuzzy/AI semantic matching。
- Probe Overlay/Draft 及字典与探针之间的导入、合并或双向同步。
- 一个 Renderer 同时抽象原位写回、Overlay、retained object 和 external protocol。
- `all_observations` 自动超时，以及以事件溯源代替当前持久模型。
