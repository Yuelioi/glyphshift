# Workflow Editor 四 Tab 任务流

## Goal

让工作流新建与编辑在多软件、大词典库下仍保持清晰的任务边界，避免固定左右栏、连续长表单、
嵌套双列和重复优先级列表造成的拥挤与滚动陷阱。

## Current

已交付。编辑器按“基础配置 / 软件与拦截 / 翻译词典 / 字体策略”分为四个顶部 Tab；各页内部保持
单列和稳定的从上到下阅读顺序。不同 Target 仍完全隔离，Dictionary 与 Font 页通过当前 Target
选择器切换配置上下文，软件页把目标选择与该目标的 Adapter 配置放在同一连续阶段。编辑 Modal
高度受视口约束并在 Tab 间保持稳定，顶部导航不参与内容滚动。

## Decisions

- 顶部 Tab 使用无图标、低对比度的紧凑分段条，问题数量直接显示在对应 Tab；切换采用手动激活，
  避免键盘经过 Tab 时意外丢失当前工作上下文。
- Modal header、分段导航和 footer 固定；当前 Tab 内容是唯一主滚动区，不再让导航旁出现贯穿式
  滚动条，也不再创建左右各自滚动的主从栏。软件、词典和字体目录具有可见高度上限与独立搜索。
- 100 份 Dictionary 直接渲染仍属轻量边界，不叠加虚拟滚动或分页；Probe 的 5000 条后端分页策略
  不复制到这里。
- Dictionary 与 Font 各自只保留一个目录列表；已选项置顶，优先级在行内调整，不再维护第二份已选
  列表。Font Policy 关闭时显示安静的说明面。
- 当前 Target 使用可搜索选择器；10 个软件时无需横向堆叠 Target 卡片，也不会挤占配置宽度。
- 搜索无结果、集合为空、目标待配置和已配置均提供明确非颜色状态。

## Verification

- 前端生产构建通过。
- 30 项仓库 Playwright 全部通过，其中覆盖四 Tab、10 个软件、100 份词典、限定滚动、搜索、
  固定 Modal 高度、无导航溢出、Target 隔离与行内优先级回归。
- Nuxt UI 组件约束与最终布局机械扫描通过。
- 使用合成数据在桌面尺寸下检查深色 Modal；真实机器截图仍只保存在本机忽略证据目录。
