# Dictionary 行内草稿编辑

## Goal

让词典作者在一张表内持续修改和新增词条，并始终明确哪些内容尚未持久化；设置、词条和退出保护
必须属于同一个草稿生命周期。

## Current

已完成。词条编辑 Modal 与页头“添加词条”已删除，现有行直接编辑，表格末行常驻空白新增入口。
设置应用、行内修改、新增和删除统一派生“未保存”状态；保存成功后由新的 `DictionaryDetail`
更新基线。返回列表、顶部导航、标题栏关闭和浏览器卸载已接入保护，其中前三者使用统一确认框。

## Decisions

- 不按每次按键写盘。用户编辑的是一份显式草稿，只有“保存词典”持久化完整 metadata 与 entries。
- 设置 Modal 的“应用设置”只应用到草稿；标题旁的“未保存”和退出保护消除已落盘的错觉。
- 空白新增行不进入持久模型；原文和译文完整、原文不重复时，按 Enter 或点击保存才提交到 entries，
  然后立即恢复新的空白行。
- 已有词条不再复制到第二套编辑状态；删除是唯一保留的行级动作。
- 空原文、空译文和重复原文就地显示错误并阻止保存，不用错误 Modal 打断连续录入。

## Verification

- 红回归首先证明旧表没有直接编辑入口；实现后聚焦 Playwright 3 项通过，覆盖 metadata 保存、
  行内修改、末行新增、未保存状态、返回/顶部导航/窗口关闭保护和保存后的纯 entry payload。
- `vue-tsc --noEmit` 与生产构建通过；完整 Playwright 39 项通过。
- 960×640 与 1440×900 视觉证据证明表格、末行新增、未保存标记和放弃确认均保持在应用视口内，
  没有恢复词条 Modal 或产生横向页面滚动。
