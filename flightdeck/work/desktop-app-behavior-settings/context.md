# 桌面应用行为设置上下文

- 当前平台只交付 Windows，窗口使用 Tauri 2 无边框标题栏。
- 管理员启动是用户明确开启的持久偏好，默认关闭。开启后立即请求 UAC，并在后续每次普通启动时
  再次请求，直到用户关闭；不能把所有写入失败归因于权限不足。
- Windows 高权限进程会阻止普通权限进程执行部分观察和注入操作；目标已退出、版本不兼容和权限不足
  仍需保持不同错误语义。
- 开机启动属于当前用户偏好，不需要管理员权限。
- 关闭行为只有 `minimize` 与 `quit`。在没有 Tray 的情况下，`minimize` 必须明确表示任务栏最小化。
- 语言、主题、启动、管理员启动和关闭行为继续由唯一 `AppSettings` 模块持久化；当前权限状态是
  运行时事实，不是持久偏好。关闭管理员启动不会让当前高权限进程原地降权，只影响下次启动。
- UAC 重启必须显式传递当前 Desktop 数据根与 Runtime 根，并在 Windows Shell 同步确认提升后的
  GUI 子进程已经创建且没有立即退出后，原进程才能结束；不能依赖提升进程继承测试环境变量，也不能
  把 UAC 请求已受理等同于应用接管成功。

## 启动时发现的后续问题

- 开发 App 必须通过 `scripts/dev-app.ps1` 启动，确保数据根与运行时证据留在 `local-test/`；不能
  为了本地预览直接读取或改写真实 AppData 工作区。
- 只读诊断发现历史 `glyphshift.workflow/1` 文件不能被当前 `glyphshift.workflow/3` 直接加载，因为旧
  Target 没有 `adapterPlan`。正式升级前需要单独设计可解释的迁移规则，不能通过删除旧工作流规避。
