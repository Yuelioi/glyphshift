# 稳定上下文

## 产品与用户意图

- Glyphshift 是面向 Windows 的高密度运行时翻译管理工具，不是营销网站或卡片式仪表盘。
- 用户认为当前整体结构可用，但视觉一致性、交互细节和操作体验仍需系统优化。
- 本阶段允许后续修改共享底层组件；当前第一步是先建立证据充分、可排序的审计基线。

## 审计范围

- 应用框架：标题栏、一级导航、页面画布、主题与语言切换。
- 管理列表：Workflow、Software、Dictionary、Probe 的页头、工具栏、表格、分页、空态和批量动作。
- 独立详情：Workflow、Software、Dictionary、Probe 的返回、标题、状态、主要动作、编辑与未保存保护。
- 工具页：Settings 与 Help 的信息分组、文案、反馈和窄窗口表现。
- 横切体验：焦点、键盘、可访问名称、错误/加载/成功状态、危险操作、响应式与中英文长度。

## 既有约束

- `DESIGN.md` 是当前视觉与交互合同；审计需要区分实现偏差与设计合同本身需要调整的地方。
- 使用仓库 Playwright CLI/test runner 检查本地 GUI；不依赖应用内浏览器。
- 960×640 与 1440×900 是现有桌面基准，深色与浅色都属于支持范围。
- 真实软件位置、进程、截图、视频与日志只能保存在忽略的 `local-test/` 下。
- 不恢复首页仪表盘、软件主从栏、营销式大卡片、大面积强调色或重复的“开始翻译”动作。

## 评审原则

- 相同对象与动作应共享组件、术语、位置、反馈和键盘行为。
- 先处理影响任务完成、误操作和认知负担的问题，再处理纯视觉润色。
- 共享组件的修复必须用代表性页面与紧凑窗口验证，避免单页局部修补造成新的分叉。

## 已固定的体验合同

- 高密度管理表在窄窗口中持续保留选择、对象身份与操作上下文，低频动作进入具名菜单。
- Probe 详情页头只承载当前任务动作，AI 翻译与条目表相邻，临时资产不向普通界面暴露内部标识。
- Help 先解决常见恢复任务，再解释产品模型与 Adapter；低频技术信息按单项渐进披露。
- 应用提供首个 Tab 可发现的主内容跳转和 `Alt+M`，共享工具栏可按名称定位，复合表面 heading 不跳级。
