# 稳定上下文

## 产品事实

- “始终以管理员身份启动”只决定 Glyphshift 自身下次启动的完整性级别，不证明任意目标一定可注入、
  可写回或未受安全软件保护。
- 用户以普通交互启动软件时，启动器仍可能自行提权并让目标子进程继承高完整性；产品提示必须依据实际
  令牌与失败操作，不能依据用户如何点击启动来推断权限。
- 探针绑定的是 Software 身份；每次连接都必须解析当前运行实例。应用提权重启前取得的 PID、句柄、
  opaque token 或 Runtime 状态都不能跨重启复用。
- “目标退出”“目标完整性更高”“访问被拒绝”“目标受保护或拒绝加载组件”“组件已加载但协议/激活失败”
  是不同恢复路径，不能共用一条要求用户反复提权的提示。
- 游戏目标可能有保护机制或自定义渲染路径；这不能通过软件品牌、可执行文件名或具体 Adapter ID 分支处理。

## 约束

- Core、Desktop 与 GUI 保持品牌无关，错误分类来自系统错误、Controller/Runtime 协议和能力事实。
- 真实目标证据只保存在被忽略的 `local-test/evidence/`；Flightdeck 只保留匿名、可复用结论。
- 目标安全拒绝必须 fail-open；不能通过关闭保护、绕过反作弊或更强注入手段完成验收。
- 普通界面不展示 PID、句柄、DLL 路径或内部 Adapter ID，但可以给出稳定错误类别和恢复动作。
- Target Process、Remote Memory、Remote Thread 与 Observer Permission 是稳定错误类别；Command Error
  使用通用操作类别，不泄露 Controller 内部实现或品牌信息。

## 验收语义

- Glyphshift 已提权且目标仍运行时，不再建议用户重复开启管理员设置。
- 目标实例在 Glyphshift 重启期间变化时，重新解析新实例；不能对旧实例写入。
- 访问拒绝、受保护目标、组件加载失败和协议激活失败分别保留可诊断语义。
- 失败不会影响目标进程，也不会把仅观察能力冒充成写回成功。
