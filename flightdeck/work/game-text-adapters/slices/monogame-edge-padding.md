# MonoGame 排版空白匹配

## Diagnosis

用户的标题和分类已显示译文，完整物品说明仍为原文。对可见物品提示开启现有 Runtime 决策追踪，实际绘制文本比词典键多了末尾 ASCII 空格，回执为 no_match；其他词条正常 matched。Capture 目录会 trim 原文，造成表中看起来相同、运行时精确键不同。

## Fix

MonoGame 原生桥接保留精确匹配优先；未命中时仅去首尾 ASCII 排版空白再次查找，保留原调用的前后空白包围译文。无需用户修改词典，也不折叠句中空白。不改变其他 Adapter 的查找行为。

加入有首尾空白的真实 Runtime 像素/测量用例，先确认旧实现失败，再验证新实现；另验证带空白精确词典键的优先级。完整 MonoGame 回归与纹理解码合同通过。实机原始 trace 只在 local-test/，未修改词典。

## Next

同步打包启动后，用户需重启目标加载新驻留组件，再复测同一条完整说明。旧进程的命中失败不能作为新组件的验证结果。
