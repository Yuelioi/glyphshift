# MonoGame 缺字字体回退

## Problem

用户已捕获原文并填写中文译文，但目标继续显示英文。原组件在译文字形不属于 SpriteFont.Characters 时保留原文，导致“采集和词典命中正常，缺字目标不可见”。

## Current

已用相同发布、完整字体/拉丁字体对照建立红灯：真实 Runtime 测试在“字典命中必须产生回退字形”断言失败。补齐后 117 帧像素与测量回归通过，原字体纹理/字符表修改 0，StringBuilder 修改 0，窗口后台缓冲区差异 0。

实现为嵌入受校验 Native DLL 的托管辅助代码，仅引用系统运行库。按目标 MonoGame 类型克隆 SpriteFont，保留原字形、图集和度量，通过 Windows 字体补缺字；新图集在 GraphicsDevice.Present 发布，下一帧测量与绘制共同使用，旧纹理在帧边界释放。无游戏专属方法、资源包或额外安装步骤。

测试覆盖两代译文，以及后续新增“斧头”字形的再发布、停用恢复；保留 34 项旧 CoreCLR 合同与 1 项 Rust Loader 互操作回归。新版本已经按同步构建脚本打包并启动，Bundle 仍为 10 个 Adapter，沿用用户配置。

## Limits

本轮回退已通过合成真实 Runtime 验证，未在仍驻留旧 DLL 的游戏中热替换。用户需重启目标后复测同一物品提示。首个缺字帧保留原文，帧边界发布后显示译文；系统字体缺字、超出缓存预算、复杂 shaping、自绘纹理不自动覆盖。

## Next

验证用户重启目标后的物品提示实机结果。不要重用老进程声称新 DLL 生效，不强制退出可能有未保存进度的游戏。
