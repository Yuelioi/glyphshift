# 工作流统一运行生命周期

Status: Implemented，Release 已启动，等待目标软件实机验收

## Goal

执行用户接受的 [运行模型](../references/workflow-lifecycle-proposal.md)，统一状态、操作、收集设置和 AI 生命周期，保留历史文字。

## Steps

- [x] 统一运行快照及状态投影，包含停止失败、检查时间、单调代次；顶部、列表、详情共用。
- [x] 统一开始/停止入口，移除启用列；等待目标不报错，切页/前台刷新、在途合并、旧响应隔离。
- [x] 收集新原文成为持久化工作流设置；迁移旧暂停意愿，重连后重新应用设置。
- [x] 自然退出保留自动补全选择并允许当前轮结束；主动停止按拥有者取消自动任务，隔离其他工作流及手动任务。
- [x] 定向自动化回归、合成页面检查、更新产品契约。

## Implemented

- Native `workflow_lifecycle` 根据启用意愿、真实 Runtime 目标与错误生成运行状态，历史观测不参与活跃判断。
- Runtime 视图携带检查时间和单调 revision；详情摘要只转发同一运行快照。前端忽略旧状态回包。
- 开始/停止按工作流串行执行；目标未运行时等待，不自动启动软件。停止未确认保持失败状态和 Runtime 所有权，可以重试，不能删除仍活跃的工作流。替换冲突工作流先走同一停止路径。
- 顶部显示各状态数量；列表与详情使用相同状态和颜色。列表提供开始/停止与查看文字，取消独立启用列。状态可查看上次检查时间。
- 进入工作流和回到 App 前台触发合并刷新；后台沿用 5 秒对齐，1 秒采集入库独立运行。刷新失败显示待确认。暂时激活超时最多自动重试三次，逐次延长间隔；明确配置/权限/驻留错误要求手动重试。手动刷新可以重试未确认的停止。
- 收集开关位于工作流字典设置和详情任务操作，关闭后翻译/字体继续工作。旧暂停记录在第一次准备工作流时迁移为持久化偏好，普通新工作流默认收集，有写入字典才可打开。
- 目标自然退出保留自动补全选择但不排新轮次；主动停止取消当前工作流拥有的自动任务，已开始任务的延迟返回也按拥有者处理。保留模型并发、全局单活动任务、公平排队和零间隔 250ms 下限。App 重启不恢复付费请求。
