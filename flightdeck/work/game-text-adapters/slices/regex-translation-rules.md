# 设置中的正则翻译规则

Status: Complete

## 目标与决定

用户明确要求字典保持普通原文/译文结构，规则放设置，每条由两个输入框构成，默认就是正则。不能按属性名逐条写固定译文；同一规则必须覆盖任意已知属性，数值原样保留。

设置新增“替换规则”分区，支持逐条添加、编辑、启停、删除、上移和下移。新增预填 `^(.+?)(:[ \t]*[0-9]+)$` 与 `{译文:$1}$2`。字典保存 `Total → 总计` 即可得到 `Total:33 → 总计:33`。本次决定取代早期研究中的“词条匹配模式”建议。

## 实现

- 核心 TranslationSnapshot 保存独立的已编译正则规则，不修改 Dictionary 包或词条格式。规则内容、顺序和启用状态进入 digest 及 Runtime publication；无规则时保留原 wire 编码。
- 完整原文查词优先；即使原路由先命中字体现有策略，也先查剩余路由的完整译文，再尝试规则。捕获组查词复用路由位置、上下文和 Adapter scope。`$n` 保留捕获，`{译文:$n}` / `{translate:$n}` 查字典，`$$` 输出美元符号。
- 按顺序选择首条匹配规则，仅替换第一个匹配片段，不递归。需要查词的捕获缺失或没有译文时保留原文，不降级成只剩数字，不继续试下一条。
- 正则在配置编译/Runtime 接收 publication 时编译，绘制时不编译。最多 64 条，模式 1024 bytes、模板 4096 bytes、源和输出 16384 bytes；RegexBuilder 限制编译与 DFA 内存。语法不支持前后查找和反向引用；输出捕获替换独立支持。[RegexBuilder](https://docs.rs/regex/latest/regex/struct.RegexBuilder.html)
- 设置校验使用与 Runtime 相同的 Rust 实现；损坏持久记录逐条隔离，非法更新不替换旧设置。编辑显式保存，草稿在会话导航期间保留。浏览器开发环境的校验替身用于页面测试，桌面使用原生校验命令。
- DesktopBackend 为规则变化递增本会话决策代次，并附加到工作流发布；恢复工作流前加载设置。后台同步发布新增、修改、停用或删除，普通设置变化不增加规则代次。

## 英文变量名与整条译文优先的澄清

预设、帮助和示例统一使用 `{translate:$1}`。已有中文变量在设置读取时规范显示为英文，Runtime 继续兼容旧写法；不改用户字典。补充帮助：字典添加 `Total → 总计`，已有 `Total:18` 整条译文必须清空才能使用正则保留数值。

合成对照复现整条 `Total:18 → 总计` 优先导致无数值，而仅属性词条加规则输出 `总计:18`。6 项核心规则合同和 4 项设置页面流程通过，包含旧配置英文显示；窄屏截图复核通过。本轮尚未重新打包 App，当前用户编辑中的规则未由代理保存或覆盖。


## 独立译文变量与单条正则测试器

用户确认使用独立 `{{TR}}` 代表第一捕获组的字典译文。预设为 `{{TR}}$2`；旧第一组写法在设置中规范展示为新变量，Runtime 保留旧语法兼容。当前只新增这一个变量，普通 `$n` 捕获组和 `$$` 原样输出继续支持。

每条已存规则和当前未保存编辑器末尾提供模拟原文、可选模拟译文和测试按钮。测试显式运行这一条，不受开关影响、不读字典、不读工作流、不保存配置。展示完整匹配及各捕获组、是否缺少模拟译文、最终替换结果；输入变更即清除旧结果，异步过期响应不能覆盖新输入。

桌面命令直接调用 core translation 的同一编译、模板解析与替换实现，模拟译文通过闭包注入。预览有输入和输出上限；浏览器开发用 JS fallback，不声称所有 Rust regex 语法可在浏览器运行。
