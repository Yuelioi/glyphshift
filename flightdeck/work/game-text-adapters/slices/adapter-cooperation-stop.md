# 多适配器协同与停止修复

Status: Implemented

## 协同事实

- Runtime 按部署列表逐个调用激活，成功者可以同时工作；至少一个候选成功即可整体成功。
- Qt Painter、DirectWrite 等完整文本入口使用线程内绘制范围，只有已输出文字替换的范围才阻止同一调用链内其他适配器重复采集/翻译；未命中和输出失败放行下层；范围退出后恢复，其他线程不受影响。这是调用范围隔离，不是全局禁用 Windows。
- GDI/Qt Painter 等原生 Hook 停用时将能力关闭并透传，保留驻留 Hook，不能把取消勾选理解为卸载所有 Hook。当前 Runtime 改变已加载适配器集合仍有生命周期限制，本轮没有加入任意热切换。
- 实际软件的初始化失败与同一次绘制内的隔离不同。用户现场非 Windows 候选无法启动仍未复现，不宣称修复。

## 已修复缺陷

停止过程原先使用有副作用的 `Iterator::all`；首个适配器停止失败会短路，使后续适配器根本没有收到停止请求。

现在先尝试所有活动适配器，再汇总结果；已停止者从活动报告移除，只保留失败者以供重试。部分失败仍报告失败，不把残留运行冒充停止成功。失败路径也请求重绘，使已退出者的原文得到刷新。

## 复现与验证

新增 `trh_006_stop_failure_does_not_leave_other_adapters_running` 使用合成 DLL 注入停止失败，并与真实 GDI 同时启用。修复前，停止失败后 GDI 仍显示译文，像素摘要未恢复；修复后恢复原文，活动报告只剩失败候选，解除故障后可再次停止。

- 红/绿命令：`cargo test -p glyphshift-target-runtime --test target_runtime_contract trh_006_ -- --ignored --test-threads=1`。运行前按仓库约定初始化 Cargo cache，并构建活动 GDI 和合成测试 DLL。
- Native 合同 5 项分别隔离执行通过：GDI 与 GDI+ 同时激活/更新/恢复、部分候选不可用、生命周期重绘、失败初始化后重试，以及新停止失败回归。
- desktop runtime 37 项与 target runtime 2 项库测试通过；后者覆盖嵌套绘制范围、其他线程独立处理及范围退出后底层恢复。合计 44 项通过。
- 没有运行归档 UIA，没有加载用户真实目标；原始日志与像素摘要仅保留在本机证据目录。
- 未重新打包 App、未提交。用户要求评审 App 时使用 `scripts/review-app.ps1`。

## 防回归结论

批量生命周期操作必须先执行每个候选，再汇总状态；不能在需要完成清理的遍历上使用短路谓词。状态报告要反映部分成功，保留失败者的重试能力。

## 未替换时放行下层

用户指出外层可能只有单字、内层才有完整句子。范围进入时不再立即排斥其他适配器；Runtime 成功写出文字替换后才标记最近的所属范围。任意已替换祖先范围保护其后代，退出时移除；线程和生命周期隔离保留。仅字体决策不触发文字保护。

扩展真实 Runtime host 回调测试：外层 `O` 未命中、下层 `Open` 可采集并翻译；输出容量不足不占用范围；内层已替换时后代受保护；内层退出后旧式回调恢复；既有跨线程和生命周期检查仍通过。先红后绿，target runtime 两项库测试通过。该标记代表 Runtime 输出替换成功，现有 ABI 没有适配器实际绘制成功回执，不冒充目标像素验收。

本次放行变更已通过 `scripts/review-app.ps1 -UseUserData` 同步构建并启动最新 App，原始及打包 Runtime Bundle 的 13 个适配器校验通过。用户真实目标的完整句子和防重复翻译效果待本机验收。
