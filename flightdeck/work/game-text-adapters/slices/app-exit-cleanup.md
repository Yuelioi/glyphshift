# 正常退出时停止目标运行效果

Status: Implemented

## 缺陷与修复

用户反馈关闭 Glyphshift 后目标仍显示译文。原窗口关闭路径直接调用窗口 close，没有准备退出命令，桌面 RunEvent 也没有停止 Runtime 的退出清理。

现在正常关闭先调用 `desktop_prepare_exit`，停止当前工作流与独立捕获、收取收录末批并触发已有原文恢复/重绘路径；成功后才允许窗口关闭。停止失败继续处理其他工作流，保留窗口和错误，允许重试。原生 ExitRequested 对程序触发的退出提供同样的清理；已完成清理可幂等复用。

退出期间暂停后台工作流协调，避免刚停止就被定时刷新再次激活。保留持久工作流启用期望，下一次启动仍按保存配置恢复；显式开始工作流可恢复协调。关闭设为最小化时仍继续运行，草稿/AI 退出确认沿用原流程。

此修复针对正常退出，不宣称强杀进程或系统崩溃也完成同步清理；驻留 DLL 本身不必卸载，停止能力和恢复原文才是本轮完成条件。

## 验证

- Playwright 在修复前检测到关闭未调用准备退出而失败；修复后验证停止失败不关闭、重试成功后关闭，以及最小化不停止，共 2 项通过。
- shell 库 108 项通过，包括退出时停止但保留持久期望、定时刷新不重启、一个工作流失败仍停止其他工作流与重试。最后幂等加固后 2 项退出合同复跑通过。
- 目标 Runtime 停止/原文恢复已有本轮 5 项 Native 回归，见多适配器协同切片；本轮没有复现用户真实目标截图，不宣称现场像素已验收。
- 最新 App 已按 `scripts/review-app.ps1 -UseUserData` 同步构建并启动。前端生产构建通过，13 个适配器 Bundle 在原目录与打包副本校验通过；进程响应、有窗口、可执行文件哈希符合评审描述。用户目标的退出恢复像素仍待本机测试。
