# 游戏引擎接入：先补接口含义，再验证真实接入

## 本次决定

保留工作流、字典、AI 和现有 Runtime。第一条新路线先做 RPG Maker MV；MZ 单独验证，不凭名字合并支持。
先用一个小原型找到真正需要的接口，不先创建覆盖所有引擎的通用框架。

## 代码里已经有什么

| 已有内容 | 代码位置 | 这次怎么用 |
|---|---|---|
| 绘制、保留对象、外部协议、只观测四种方式 | `crates/core/domain/src/lib.rs` 的 `ApplyModel` | 继续沿用；外部协议枚举不代表已经能接入 JS |
| 完整文本、片段、结束、取消与字形证据 | `crates/core/domain/src/text_run.rs` | 完整对白走完整文本；拼出全文也不能倒过来修改已经画完的字 |
| 上下文与有序字典决策 | domain 的 `TextObservation`、runtime contract 的 `WireTranslation` | 不建第二套字典查找；引擎补充上下文的来源 |
| 代次与文字 Host 扩展 | `crates/adapters/platform/native-abi/src/text_host.rs` | 后续 JS 桥连接已有决策，不在桥内访问 AI |
| 异步刷新请求 | Native ABI 的 `RequestRefreshV1` | 只是请求，不证明目标真的重画了；不能据此显示刷新成功 |
| 停用与进程驻留说明 | Native ABI `deactivate`、desktop bundle 的驻留字段 | 分别说明行为恢复和代码是否卸载 |
| 文件导入导出处理器 | `crates/product/desktop-backend/src/dictionary_transfer/` | JSON/CSV/SRT 与后续 XML 留在文件层 |

## 职责怎么分

运行环境接入负责找到正确的进程与脚本执行环境，校验目标身份和版本，传递当前词典代次，
在正确线程调用引擎入口，并处理断开和退出。它不理解对白，也不改存档。

引擎适配器负责辨认完整对白和选择项，保留原文，处理变量与格式，找到可安全替换和重绘的位置。
它不知道 AI 服务和磁盘字典路径。MV 与 Tyrano 即使都使用 JS，也不能共用同一套对白处理。

现有 Runtime 继续负责授权、字典顺序、查找、采集和 AI 结果发布。JS/Python 桥最终复用这套能力；
在有第二个真实调用方前不抽象通用 Bridge 基类，也不引入无使用者的新 crate。

## 能力要说清楚

| 能力 | 含义 | 不能据此推导 |
|---|---|---|
| 观测 | 入口提供了完整原文 | 最终像素可见或译文已显示 |
| 预采集 | 从明确的已加载显示数据取到原文 | 游戏全部文本、当前画面命中 |
| 下次显示替换 | 下次进入文字入口时能使用译文 | 当前画面自动更新 |
| 当前画面更新 | 同一条对白在安全边界换成新译文 | 重播事件、重新触发选择或控制符是可接受的 |
| 当前画面恢复 | 停用后当前内容回到原文 | 组件已经从进程卸载 |
| 字体与比例 | 引擎有经过验证的字体或布局入口 | 所有引擎通用支持 |

这组描述先用于原型验收，不直接给所有现有适配器补默认 true。
正式声明应是每项明确支持、不支持或未验证；没有证据时不能按函数存在推成支持。
Native ABI V1 的结构大小校验必须保留；确需新增协商信息时沿用可选版本化扩展，不能直接加结构字段。

## 文字与会话约束

- 展示入口观测、资源预采集、可见替换结果分别记账。预采集不能增加实时命中次数。
- 原文和上下文不被译文覆盖；变量值、样式、暂停和事件控制由引擎适配器解析，不能全局替换所有字符串。
- 同一逻辑对白保持稳定身份；画面已进入下一条时，旧异步结果只能进入字典，不能覆盖新对白。
- 请求要绑定目标实例、会话和 publication 代次；重连后丢弃旧请求。使用有界队列与长度限制。
- 游戏线程只查当前快照，不等 AI、不访问网络。宿主断开或输入不支持时继续原来的显示流程。
- 停用撤销自己的入口并在引擎安全边界恢复自己管理的画面；不覆盖之后安装的第三方 Hook。
- 变量与格式第一阶段透传，后续先证明保留规则再允许替换。不能让译文新增执行控制符。

## 首个原型的结果和边界

[合同原型](../../../../test-support/rpgmaker-mv-text/README.md) 在 `startMessage` 的局部转换阶段取得完整对白。
合成测试验证完整多行文本、下次对白更新、停用后新对白恢复、异常透传、重入保护和 Hook 所有权。
它不写消息源，不重放事件，不触碰其他转换调用。格式化文本先只观测。

后续已验证普通发布运行器的窄版本原生入口并接通正式 Runtime 采集与 publication，见 [MV 运行器接入实验](mv-runtime-entry-validation.md)。仍没有商业目标验收、当前画面刷新与恢复，原生接入仍依赖实验驱动。
合成回调验证的是接口含义，不是 JS 到 Native 的真实传输或目标像素。原型不进入产品支持列表。
MV 的 `startMessage` 会准备新页，正文还会触发暂停和选择；简单重调该方法不能当作刷新实现。
依据：[MV 官方消息窗口源码](https://github.com/rpgtkoolmv/corescript/blob/master/js/rpg_windows/Window_Message.js)。

## 正式接入的顺序

先证明无需修改安装文件的 NW.js 接入，确认执行环境、版本、会话生命周期与失联透传。
仅凭公开源码找到函数，或者开发版能调试，不等于成品游戏能进入该环境。

接入可行后把同步回调接到 Runtime publication/采集；再实现只重绘当前文字的安全入口，
覆盖逐字中途、等待确认、选择项、跨页和停用。字体和控制符各自补合同。
最后用两个独立授权目标验证首代译文、下一代更新和停用恢复，才进入正式 Bundle 与 Catalog。

若无修改安装文件的接入方式不可行，保存 No-Go 结果并转下一条路线；不默默改成插件安装或文件替换。

## 与正式文字 Host 对齐

已审计 target runtime 的 `text_host::decide_text` 和 `decide_source`：同一次请求先采集，再按使用方式决定是否查词。MV 原型改为一个 `resolve` 请求，普通文本映射 `TEXT_EVENT_DRAW`，未支持的控制符映射 `TEXT_EVENT_OBSERVE`。不能再各发一次 observe 和 decide，否则同一次显示可能重复计数。12 项合成合同覆盖单次采集与只观测不替换；后续真实运行器合同也已证明同一语义通过生产回调成立。
