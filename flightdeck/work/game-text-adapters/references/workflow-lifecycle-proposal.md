# 统一工作流运行模型提案

Status: Accepted；实现与验证记录见 [执行 Slice](../slices/workflow-lifecycle.md)，实机新包验收待进行。

## 产品目标

用户维护一个工作流，通过一次开始/停止控制它对目标软件的翻译、字体与可选新原文收集。界面明确交代当前正在做什么、为何等待、需要用户做什么。用户不维护另一套探针运行状态。

保留用户要求的单软件工作流、不同软件多个工作流同时运行、独立字典及原文排除规则。运行历史不是活跃进程的证明。

## 已发现的现有冲突

见 [调查报告](workflow-state-review.md)：顶部采集缓存与列表运行时快照不同步已复现；切回工作流没有立即刷新。

继续检查代码还发现：列表开启工作流可以保留等待意愿，详情 resume_probe_run 则在没有 active target 时返回 target_not_found；相同开始意图被不同入口解释。disable_workflow 先移除启用意愿再执行 stop，列表 actualStatus 又先检查启用，因此停止失败可能被已停用遮住。这两点为代码路径结论，未执行新的原生故障注入。

## 用户操作

只保留一套“开始运行／停止运行”。建议主列表移除单独“启用”列，用状态加开始/停止操作，与详情按钮发往同一入口。启用意愿留在底层，不再让用户同时理解开关和运行状态。若停止失败，必须显示“停止失败”，不能因内部意愿已关闭就显示已停止。

开始表示在 Glyphshift 工作期间接管所选软件。软件尚未打开时进入“等待软件启动”，正常等待不报错，不自动启动该软件。运行软件作为独立便利操作保留。

目标自然退出时回到等待，保留本次启用意愿；重开软件自动连接。用户明确停止时取消等待、重连和该工作流的自动补全调度。

启用意愿沿用现有持久化行为；Glyphshift 重开后重新确认目标，旧历史 running 不能直接恢复绿色状态。付费 AI 自动补全不因 App 重开自动恢复，保持现有约定。

## 收集改为行为设置

将“暂停收集／继续收集”统一成“收集新原文”设置，默认开启，在任务操作中可以切换；关闭时显示一条简短说明“仅使用已有字典，不收集新原文”。不为它建立第二套运行按钮或顶部运行标记。

关闭只控制新原文收集，不停止已有译文替换或字体效果，不删除历史条目，不清空排队保存的数据。再次打开只承诺从之后观察到的文字继续收集，不承诺补回关闭期间全部文字。

设置按工作流保存，目标退出重开后保持选择。无写入字典时明确不可开启收集；允许仅应用已有字典或字体的工作流，不因没有采集记录把它判断为停止。

“隐藏跳过条目”仍是视图筛选，不能替代收集设置。

## 用户可见状态与转换

| 场景 | 主状态 | 主要操作 |
| --- | --- | --- |
| 从未开始，或已确认停止 | 已停止 | 开始运行 |
| 已开始，尚无匹配的目标进程 | 等待软件启动 | 停止运行；任务操作中运行软件 |
| 正在获取/建立目标会话 | 正在连接 | 允许停止，取消未完成连接 |
| 本次会话确认正常 | 运行中 | 停止运行 |
| 软件正常退出，但用户未停止 | 等待软件启动 | 等待重开，或停止 |
| 用户停止，尚未确认目标撤销 | 正在停止 | 显示进度，防止重复命令 |
| 权限、协议、配置或驻留旧版本阻止连接 | 连接失败或需要重启软件 | 显示具体原因与重试操作 |
| 停止被目标拒绝/无法确认撤销 | 停止失败 | 重试停止，或提示退出目标；不能宣布已停止 |
| 无法取得近期可信状态 | 状态待确认 | 保留上次检查时间，重试检查 |

运行中只表示 Glyphshift 已确认本次会话和实际生效能力，不承诺当前画面每一处文字可翻译。采到文字的条数、过去存在的进程、启用开关均不能单独证明运行中。

能力另用简短说明表达：文字替换、字体设置、仅能收集等。默认全选适配器时，未匹配当前软件的适配器是正常情况，不按成功适配器比例报异常。当前需要的关键能力缺失才提示限制；例如只能收集却不能替换，不能给用户完整翻译已生效的印象。空字典暂时没有匹配译文不是适配器连接失败。

## 顶部、列表和详情

三处消费同一份按 workflowId 标识的权威运行快照，前端仅做文案与格式化。采集记录只负责原文、次数、来源及历史查询，不再提供工作流生命周期判断。

顶部明确全局范围：有实际运行的工作流显示“运行中 · N”；仅等待时显示“等待 · N”；全部已确认停止时不显示绿色徽标。有失败/待确认项同时保留可见的问题提示，不能被另一正常工作流覆盖。展开显示各工作流名称与状态，解决当前软件与全局汇总的歧义。

例：两个软件，一个正常退出、另一个仍运行，顶部是运行中 1，列表分别是等待与运行中。两个都退出且继续启用，顶部只能显示等待，不能继续显示运行中。

## AI 行为

自动补全是该工作流运行期间的辅助行为。收集新原文设置关闭不必阻止翻译字典内已有待译项；两者的职责分别是新增原文和补译文。

- 目标自然退出：停止发起后续自动补全轮次；当前已经启动的一轮允许完成并保存结果。保持本次自动补全选择，目标重新连接后可继续。
- 用户主动停止工作流：取消该工作流排队的自动补全，并取消其当前自动任务后续请求；已经返回的结果仍按冲突规则保存，取消过程中不承诺零在途请求。取消范围使用任务拥有者，不能停掉另一个工作流或手动字典任务。
- 手动发起的字典 AI 任务独立运行，停止目标软件不取消它；界面可在任务区域说明仍有 AI 任务。
- App 重启不自动恢复付费请求。现有全局单活动 AI 任务、任务内模型并发设置与公平排队约束保留。

上述退出/停止差别已落到工作流停止通知和任务拥有者取消合同；普通取消自动补全选择仍只停止后续调度。

## 内部设计

设置、用户意愿与实际运行事实分别保存，由一个工作流运行模块组合为快照，不把这些字段分别交给各个页面猜状态。

最小内部信息：启用意愿、收集设置、会话阶段、会话身份、已确认能力、最近确认时间、结构化失败原因、操作代次。状态未知与已停止不同；停止指令已发出与停止已确认不同。

外部入口集中为开始/停止、修改收集设置、读取/刷新状态。列表、详情和快捷键调用同一入口。模块封装目标发现、会话所有权、适配器启停、末尾采集保存与自动补全通知；不再增加包装旧探针状态的第二层推断器。

读取状态与执行状态对齐分开：查看页面和查询状态不应重注入、重建翻译规则或刷新目标画面。需重连时由明确的会话调度处理，只有最新启用意愿仍成立才执行。

每个工作流独立序列化操作。开始后立即停止会使旧连接结果失效；旧会话退出事件不能清掉新会话，依据会话身份和操作代次判断。同一目标进程不允许两个工作流抢占，其他软件可独立启停。

停止完成须由运行层确认已经停用其作用并处理末尾采集；驻留模块尚在内存不等于仍在翻译，也不应强制卸载。保留各 Adapter 已知撤销与画面更新限制；无法确认时明确提示。

## 更新与重试

- 打开工作流页、回到 App 前台立即请求最新状态；同类在途请求合并。
- 开始、停止、目标退出/重连后发布统一快照；事件暂缺时用受控后台检查兜底。
- 不要让顶部、列表、详情分别定时查询并修改自己的活动状态。原文采集的每秒检查与运行状态检查继续分开。
- 运行状态检查使用进程/会话证据，不能用“最近几秒没有新文字”判断退出。
- 暂时没有进程属于等待；明确配置/权限/驻留版本错误需要处理。不能对所有失败每几秒无差别重试注入；可恢复故障采取有界退避，用户手动重试可立即触发。
- 状态发布带单调代次，旧异步结果不能覆盖较新的状态。检查失败会显示待确认和上次确认时间，不悄悄长期保留绿色状态。

## 实施与验收顺序

1. 固定状态表及失败语义，提取现有生命周期权威模块，用同一快照替换顶部、列表、详情的数据源；先修复现有已复现缓存缺口。
2. 列表、详情、快捷键统一开始/停止；加入切页刷新、旧响应隔离、停止失败展示与退出等待行为。
3. 用收集设置取代生命周期 Paused；明确旧暂停状态迁移，普通工作流默认开启，历史采集记录不删除。接入能力与 AI 拥有者取消逻辑。
4. 验证通过后再清理旧探针生命周期字段和接口，仍有调用的历史/导入/AI 功能逐一迁移，避免重复此前仅删界面的合并问题。

必要合同：未打开软件先开始；目标自然退出与重开；主动停止后目标重开不重连；暂停/关闭收集后目标重开；连接中立即停止；停止拒绝；旧响应覆盖；多个工作流仅一个退出；同目标冲突；无写入字典及字体工作流；全部适配器无匹配与部分适配器正常；状态检查失败；AI 排队取消、在途结果保存、其他工作流不受影响；App 重启；状态读取不造成重绘/重注入。

不以换文案或新增定时器作为完成标准。以相同场景下三处状态一致、用户操作结果可预测、退出与停止语义明确作为验收标准。
