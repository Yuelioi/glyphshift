# 稳定上下文

## 产品事实

- 258 条、单批 50 会生成 6 个批次；并发 3 表示最多 3 个 Provider 请求同时进行，不是只生成 3 批。
- 当前运行时为每个 Worker 独立领取批次，HTTP 层无全局互斥锁。
- 当前界面的“批次 1/6”是累计完成数，不是编号为 1 的批次，且无法暴露超时重试。

## 用户需求

- 进度区显示运行中、排队、已完成数量。
- 每批显示状态、条目数、耗时、尝试次数及可恢复错误。
- 停止后用户可立即看到未完成批次已取消，迟到结果不写回。

## 约束

- 快照和界面不显示 API 密钥、原始响应、完整请求体或本机路径。
- 任务时间使用单调时钟耗时，对外序列化为毫秒数，不把本机绝对时间当成协议语义。
- 本机真实请求证据只能保存到 `local-test/`。

## 已确认契约

- `running` 只表示 Provider 请求正在进行；重试退避窗口独立表示为 `retrying`。
- `peakConcurrency` 记录任务生命期内已观测的同时 Provider 请求峰值，不用 Profile 上限冒充实际值。
- 终态保留每批耗时、尝试次数和最后安全错误，以支持任务结束后的吞吐诊断。
