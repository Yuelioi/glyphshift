# CatSystem2 原生正文适配器

## Scope

用户要求将已证明的完整正文入口接入正式适配器，并启动最新 App 供真机测试。当前覆盖 CatSystem2 MSVC x86 UTF-8 文字对象，保留实验标识。它不按游戏名识别，不包含实机地址或台词。

## Current

- 包 `glyphshift-adapter-catsystem2-native` 已实现；Adapter ID 为 `windows.catsystem2.utf8-text`，声明 `RetainedObject`、文字采集和替换。
- RTTI、命令表、setter/append 的参数与缓冲数据流、getter、析构、末尾标记方法及显示/完成方法共同推导入口及成员位置。识别器已与实机只读映像对应，未知或歧义形态拒绝。
- 对象回调能观察已经缓存的正文；字典代次请求在目标线程处理，并每秒补充观测。目标自身 setter 复制输入，不发布借用字符串指针。保留原文与最后应用值，追加前恢复原文，销毁时移除记录；外部修改不覆盖。
- 单条最多 8192 个 UTF-8 字节，最多 256 个记录，原文/译文载荷最多 4 MiB；超过预算的新对象透传，旧记录继续用于恢复。
- 停用等待同线程回调恢复包含隐藏对象的记录；三秒无回调返回失败，后续回调继续恢复。detour 与模块留驻到目标退出。
- 新适配器已加入默认 Bundle/Catalog，指定脚本已同步构建和启动最新 Release App，生产加载器验证 13 个逻辑适配器。未作新的 Git 提交。

## 刷新故障结论

实际显示的正文末尾包含一个或多个 `FF FF` 标记；旧读取函数将整个缓冲作为 UTF-8 验证，错误跳过它。另一个没有标记的重复对象仍可捕获并替换，因此“次数递增、有译文”不代表当前画面更新。每秒观测保留以支持恢复采集，不当作刷新成功信号。

setter 单独调用会清空当前字形显示，必须再提交引擎自己的显示与完成当前文字指令。识别器从 marker 命令调用已验证 append 的关系、相邻显示方法的数据流、setter 共用成员以及 skip 命令校验入口；无实机固定地址。正文末尾标记原样保留，非法编码或内嵌未知标记透传。手动刷新相同译文也重试已替换的带标记对象，周期观测不重复刷新。

实机局部实验已显示英文替换并恢复原文，中文也能更新但有缺字；尚未定位字形缺失原因，不能宣称任意中文正确。原始/恢复截图人工核对通过。仅以像素变化判断成功的早期脚本也会放过空白，故不计作严格可见验收；合成合同改为断言独立显示缓存的完整内容。正式 DLL 的新入口与只读映像对应，生产 App 端到端仍需新游戏实例复测。

## 历史页补充

用户确认新游戏实例仍无法刷新，截图为历史记录页。已核对其实际加载的新 Bundle；排除未重启和工件版本问题。历史页正文没有末尾标记，直接从 setter 调用显示方法，不运行普通正文对象回调；其容器使用另一回调。因此上轮只修正文标记和普通 tick，不能覆盖历史页。

新增显示入口拦截，在实际提交显示时保留原文/应用值并决策；从历史容器 RTTI 推导其回调，在目标线程复用对象更新与恢复检查。未使用实机地址，不修改历史存档或推进剧情。仅更新已观察到显示入口的对象；连接时已打开的历史页需要重开，暂不枚举旧行。

本地历史行实验的未替换模式像素交并比为 1.0，替换模式约 0.128；完整英文替换和恢复画面人工核对通过。初次实验选错行区域造成假阴性，修正区域后分别重跑两模式。正式旧 DLL 在独立历史显示缓存断言失败；新 DLL 两种布局通过首代、次代、同译文重试、释放恢复与 Host 重入合同。3 项单元、三种错误形态拒绝和严格 x86 Clippy 通过。新历史入口与只读实机映像对应。生产 App 的历史页端到端仍待用户复测。

用户要求的常驻刷新成功提示已移除，说明放在按钮原生 hover title，失败提示保留。用户已恢复提交授权；适配器保留实验标识，正式验收等待另 2～3 个游戏验证。
