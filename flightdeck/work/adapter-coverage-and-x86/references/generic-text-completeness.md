# 通用文字完整性方案

本文保留设计依据与阶段研究。当前实施/验证状态以 [改动与证据整理](implementation-review.md) 和工作页为准；用户已暂停实机推进。

用户明确要求跨软件复用，求生之路仅是复现样本。产品实现不能按游戏名、可执行文件路径、样本地址或词句白名单选择规则。临时观察原型不进入产品。

## 已验证的问题

现有 CaptureObservationRecord 只提供 sequence、adapter_id 和 source。目录进一步按原文归并；没有控件身份、绘制对象、坐标、帧或文字运行段信息。因此两个独立标签分别输出一个字符，与同一词组分两次输出字符，可以得到无法区分的输入。全局按顺序拼字无法正确处理两种情况。

游戏重启后，临时观察原型经生产 Controller 激活和停用成功。前台重绘获得 13 条非合成完整文本事件，其中 11 条测量、2 条绘制。测量入口的覆盖并不等于绘制入口覆盖，也不能证明所有菜单可替换。证据仅存于本地测试目录。

## 共用模块的职责

Adapter 提供有依据的文字来源事实，Core 决定这些事实能否形成完整文本及能否交给替换通路。建议由同一个文字完整性模块接受三类输入：

| 来源事实 | Core 处理 | 替换条件 |
| --- | --- | --- |
| 完整逻辑文本及原始对象/调用关联 | 保留完整边界，可直接使用现有匹配与词典 | 对应完整绘制调用或可恢复文字对象可用 |
| 可定位的文字片段 | 只在同一对象、运行段及明确结束事件内重组；保留来源映射 | 需有能原子替换完整运行段的 Adapter 能力；仅能重组观察记录时不声明 TextReplace |
| 字形栅格化或纹理缓存事件 | 标记为字形来源，作为诊断证据，不当作完整词条 | 返回上层逻辑文字入口；单靠字形缓存不能恢复句子 |

旧 Adapter 没有提供来源事实时按“未分类”保留，不自动假定为字形，也不按单字长度过滤合法短标签。不能用 DLL 存在、DC 为内存 DC 或字数为 1，单独证明字形缓存来源。

## Adapter 与通用性的关系

Qt、DirectWrite、MonoGame、VGUI 等提供各自框架的完整文本/布局入口。ABI profile 依据公开框架版本、架构、接口与结构契约；框架 Adapter 可跨采用同一技术的应用复用。框架差异留在 Adapter，文字完整性、重组、去重和替换资格留在 Core。

VGUI 的验证样本仅证明整段入口可以被观测。正式 profile 仍需核对不同接口布局，不能只凭相同的 VGUI_Surface031 字符串套用某个样本的虚表位置。

## 迁移与验收约束

- 通过可协商扩展携带来源、运行段身份和替换目标关联，保留原 Native ABI V1 的兼容路径；不能静默改变其结构大小。
- 采集和渲染的来源元数据必须在进入去重目录前保留；事后给已归并单字补坐标没有意义。
- 完整来源与底层来源的去重应依据同一运行段/对象关联，不能因某完整句子含有某个字就删除所有同名单字。
- 重组不能跨窗口、绘制对象、字体布局上下文或明确的帧/段落边界；缺失结束事件、乱序、丢包和预算耗尽均不能产出假定完整的词条。
- 验收包含中文/英文逐字调用、合法单字标签、重复字符、两个相邻独立控件、离屏字形缓存、重绘去重、更新和停用恢复。
- 至少用两种不同文字输入通路验证同一 Core 接口，不能只为 VGUI 添加一个名义上的“通用”包装。

## 已落地的共用实现

- [TextRunResolver](../../../../crates/core/domain/src/text_run.rs) 位于架构无关 Domain：处理完整文本、有明确身份和顺序的片段、结束/取消及字形来源；限制并行段和 UTF-16 总长度，保留合法单字、空格、重复字符和分片代理对。
- [NativeTextHostV1](../../../../crates/adapters/platform/native-abi/src/text_host.rs) 是可选绑定扩展，没有改变 NativeRuntimeHostV1 的结构或已有 wire schema。没有扩展的 Adapter 继续使用 V1；新 Adapter 接受旧宿主时清除可选绑定并走旧路径。
- [Runtime 接入](../../../../crates/runtime/targets/runtime/src/text_host.rs) 在写入采集队列和执行匹配前解析来源事实。片段只有显式 Finish 且数量/顺序完整才能进入观察目录；测量与重组结果不返回替换决策。暂停/恢复、换代和停用清理未完成的段，坏元数据不能遗留可误发布的前缀。
- 完整调用范围按线程维护：外层完整文本调用拥有其下属字形回调的文字语义；不同 Adapter 的下属回调不再重复入库或替换。范围结束后、其他线程以及独立的 GDI 调用保持可用，不使用进程名或全局单字过滤。
- Qt Painter 和 DirectWrite 已接入结构化完整文本和调用范围。尚未迁移的 Adapter 保留旧行为；新的片段来源仍需由对应 Adapter 提供真实的段身份与结束事实。

## 实现验证与剩余范围

活动包回归 501 passed、0 failed、25 ignored；受影响生产库严格 Clippy 通过（上游 retour 的既有非目标 ABI 告警未作为依赖错误）。Domain 完整性契约、Runtime 的观察/替换资格、跨线程/嵌套范围、暂停清理和坏元数据用例通过。

独立 MSVC Qt 夹具内部调用真实 GDI，生产 Qt Adapter、GDI Adapter 与 Runtime 同时运行：裸 GDI 路径复现四个单字；完整 Qt 调用只留下完整原文；换代、停用恢复以及范围外单字均通过。相同合同在 x86 和 x64 通过。Qt、DirectWrite 的新旧绑定兼容及原有原生合同也通过。

这些实现验证了共用机制。VGUI 已有下文所述的实验入口接入，但尚未晋级产品，也不宣称求生之路的单字问题已经修复。临时 VGUI 样本探针仍只用于证据采集；后续须以框架接口/对象契约接入共用机制，不携带游戏路径、样本地址或专用词句。

进一步核对到多个模块静态包含 TextImage。公共 GetText 和 Paint 的存在不能证明私有对象布局、换行、颜色流及所有权语义一致；仅匹配 RTTI 类名和少数访问器指令不足以安全重画任意版本的对象。未验证的类布局实现已撤出，未加入产品。最新 App 已包含经过验证的 Core、Qt 和 DirectWrite 改动，版本仍为 0.3.0。

## 延迟绘制接入

后续改为保留原生字形调用的完整事务，而非重建私有文字对象。Domain 新增 DeferredTextDraw：只有尚未实际绘制、相同样式/基线且原生 advance 与明确位置连续的调用，才能在绘制边界结束时形成新的完整绘制输入；无法确定时将未消费的当前调用交还调用者，与缓冲前缀按原顺序重放。该模型已有四项定向测试。

VGUI 原生接入使用标准 IImage::Paint 边界、公开 Surface 绘制接口和可验证的 MSVC 调用约定。它不读取文字对象的私有字符串、换行或颜色流。未知接口通过保留原始参数/寄存器/FP 状态的转发入口处理，在执行未知操作前重放已缓存调用。暂停后的字形不被当作过去的观察记录追溯修改：实际绘制此前尚未提交，区别于 TextRunResolver 的纯观察重组。

两个独立 C++ 文字模块具有不同私有内存布局，测试了整句替换、换代、停用、宽度拒绝，以及未知操作、间距/样式变化时坐标、颜色、执行顺序、浮点返回与 LastError 的原样保留。另有错误 ABI 拒绝合同，确认接口表在校验失败时不变。全部定向合同通过，原生 x86 库严格 Clippy 通过。

新 VGUI 适配器尚未加入默认 Bundle/Catalog。重启后实机激活成功，已取得完整字幕及菜单标题/说明，但首次替换为零命中且无像素变化。新增回归确认打包颜色状态遗漏与完整 PrintText 的外层 Paint 限制：修正前失败，修正后首代、换代、停用、超宽拒绝和未知调用回退均通过。这是该阶段的合同与候选包结果；后续实机结论见下文，不能据此声称游戏已修复。

## 公开控件绘制上下文

后续前台定时截图证实：PrintText 两代替换决策及测量接受仍不足以改变主菜单像素；标准 TextImage 主要覆盖另一组列表文本。仅放开继承同一已验证 Paint 的派生类不能解决该样本的自定义绘制。该继承行为已有独立回归，但不作为实机修复证据。

[Valve Panel 实现](https://github.com/ValveSoftware/source-sdk-2013/blob/master/src/vgui2/vgui_controls/Panel.cpp) 使用公开 Surface 的 PushMakeCurrent / PopMakeCurrent 包围控件 Paint；它提供控件身份和配对的绘制范围。适配器因此新增上下文配对，在原生 Pop 之前完成延迟提交，保留当前坐标变换与裁剪。方法槽来自已有 Surface ABI profile，并核对 x86 栈清理；不读取 Panel 私有布局，也不识别游戏类名。

独立合同覆盖普通自绘、嵌套、错误配对、嵌套超限后的恢复，以及更新、停用、宽度拒绝。实机公开上下文激活和停用已通过，未归属的逐字调用归零，但菜单仍因未知操作/状态不全回退。另有先失败再修复的用例：完整 PrintText 出现在尚为空的延迟段之前，不应把后续绘制段永久禁用；有已缓存前缀时仍必须重放并拒绝合并。


## 光标推进候选与暂停点

独立夹具新增一次设置坐标后连续 DrawUnicodeChar 的模式，复现了缓存首字后错误要求再次设置坐标的问题。候选实现用已校验的原生 advance 维护暂存光标，并检查加法溢出；显式坐标、样式、间距及未知操作的原有回退仍保留。该模式的更新、超宽回退和停用合同通过。

实机最后记录到的缺失状态是多条件同时失效，不能证明光标推进就是主菜单根因。候选已经载入，随后采集发生在启动提示页，返回主菜单后用户暂停；没有取得新候选的主菜单可见替换证据。下一轮须从首次失效条件与对应画面收口，不能重复把合成通过或非零决策算作成功。
