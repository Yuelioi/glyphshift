# 扩大 VGUI 可见翻译覆盖

## 已确认与未确认

用户明确不再处理 GDI 单字；验收目标是尽量覆盖实际翻译，不能停在提取。最新探针为 318 条 VGUI 完整文字和 6 条单字。用户截图和反馈确认部分标签/说明中译英成功、释放连接可恢复；部分已配置译文的短标签未变化。原始词句、词典及机器证据仅在本地测试目录。

当前实现仅替换 Find / GetValueByIndex 返回值。plain_label 限制 256 个 UTF-16 单位，拒绝控制字符和百分号；Host 返回替换决策之后，Adapter 仍可能因标签限制或返回池状态回退。因此 Core 的替换决策不是 Adapter 实际发布指针或控件可见更新的证明。

用户随后验证：先配置译文，再重启游戏，原先未变的文字可以翻译。此对照强烈支持已有控件缓存为该批失败的主因；仍不能外推所有格式化、长度或非标准控件失败均属同一原因。

## 实施优先级

1. 选成功和失败的已配译文短标签，逐词核对精确原文、字典代次、查询是否发生、Adapter 是否实际接受及可见变化。比较保持页面和正常重建页面；只改变一个条件。诊断区分 Core 命中与 Adapter 实际接受。
2. 优先调查完整文字控件写入层。保留查询入口用于 token 与原文关联；核实实际目标的 Label / TextImage 或对应控件完整文字 setter。需要绑定存活对象、保留目标当前原文与最后应用值、在目标 UI 线程随字典更新重设文字并使布局失效。目标自身更新文字时更新原文基线，防止译文再次作为原文匹配；销毁时移除对象。
3. 仅 Hook SetText 不会覆盖启用前已经存在且不再设置的控件。必须另行证明存量对象发现或在其正常布局/绘制入口识别对象的方式，再调用已验证 setter；不能从任意线程枚举后直接写未知字段，也不能修改未经确认的虚表槽位。
4. 停用在同一 UI 线程恢复仍归本次替换所有的控件，重新计算布局；控件已被游戏修改或销毁时不能恢复陈旧快照。不能只移除 Hook 并宣称画面已恢复。
5. 随后处理格式化和多行：核对 ConstructString 等实际 ABI，保留占位符与参数语义，在有界输出或最终控件完整文字层决定替换。不能直接删除百分号保护；长度、换行和布局扩展都需独立合同。

## 上游依据及适用边界

Valve SDK 的 [TextImage.cpp](https://github.com/ValveSoftware/source-sdk-2013/blob/master/src/vgui2/vgui_controls/TextImage.cpp) 显示本地化结果被复制到控件自身缓冲，Paint 使用该缓冲。只改后续查询返回值无法更新此前副本。

[Label.cpp](https://github.com/ValveSoftware/source-sdk-2013/blob/master/src/vgui2/vgui_controls/Label.cpp) 显示宽字符 SetText、布局失效及重绘路径，以及 ConstructString 后再次设置控件文字的路径。它支持优先调查控件写入层的方向，不证明授权游戏的对象布局、ABI 或相同实现；实际接入必须另行验证。

## 验收

主菜单、设置标签、下拉选项、动态说明及含参数文字分别列出已配译文的可见覆盖。每项验证晚启用、字典第二代、游戏自身改字、页面重建和停用恢复。使用完整真实文字写入及目标像素断言；不能用记录数、成功提取或单个标签替换作为全覆盖结论。本轮形成方案，尚未实现新控件写回。

## 刷新接入的具体调查结果

代码确认：Runtime 的 `update_publication` 在应用字典代次并释放 Runtime 锁后调用 `request_adapter_refreshes`；VGUI Adapter 当前把 `request_refresh` 接为 `request_refresh_noop`。因此已有通知链可复用，缺少的是 Adapter 内的控件更新实现，不能只把回调改成 Win32 重绘。

优先验证 VGUI 标准控件消息协议，而非直接修改 TextImage 字段：

- `IPanel::RequestInfo` 可向控件请求信息，标准 Label 处理 `GetText`；`Label::OnSetText` 处理 `SetText` 消息中的字符串或宽字符串，随后进入布局失效与重绘。SDK 的 GetText 有短缓冲限制，必须识别截断，不能拿截断原文回写。
- `IVGui` 提供 PanelToHandle / HandleToPanel 及消息队列；使用带寿命校验的句柄，在已验证的 UI 线程执行读取、比较和更新。不能假设 PostMessage 从任意线程调用都安全。
- 初始刷新需要发现已存在的目标控件。只有“当前文字 → 原文/译文”记录不足以应对此前查询层已返回译文的控件：需要在查询与控件建立时保留可靠来源关联；无法关联时不能通过全局反向字典猜测原文。
- 用原始本地化标识重新 SetText 可保留控件来源语义，前提是可可靠取得标识；直接宽字符串回写可能清除原本的标识，影响后续对话变量更新，因此需明确保留/恢复策略。
- 更新合并至最新代次；停用要在清除 Host 之前完成需要的恢复并等待 UI 线程确认，失败不能报恢复成功。

[Valve Label 消息实现](https://github.com/ValveSoftware/source-sdk-2013/blob/master/src/vgui2/vgui_controls/Label.cpp)、[IPanel](https://github.com/ValveSoftware/source-sdk-2013/blob/master/src/public/vgui/IPanel.h)、[IVGui](https://github.com/ValveSoftware/source-sdk-2013/blob/master/src/public/vgui/IVGui.h) 提供上述候选机制。维护者的 [l4d2 Label 分支](https://github.com/alliedmodders/hl2sdk/blob/l4d2/vgui2/vgui_controls/Label.cpp) 也包含控件设置后布局/重绘路径；均非当前游戏二进制 ABI 的认证。

最小实机验证应保持同一个菜单对象：首次更新 → 第二代更新 → 停用恢复，全程不重启游戏、不关闭重开菜单。当前仅完成源码调查和接入方案，未实现或验证新的刷新能力。

## 已执行的同菜单刷新验证

本轮研究后执行受控原生控件 setter 实验：从实际 VGUI 调用现场取得存活面板，经 RTTI 和简单 getter 找到标准 TextImage 成员，核对完整原文、原本地化索引及 Label 宽字符 setter 的调用约定与布局/重绘调用。所有样本地址、槽位、偏移仅在本地实验配置，未加入产品。

同一个主菜单按钮在同一 UI 线程完成首版英文、第二版英文、原中文恢复，菜单未关闭、游戏未重启。对象和索引保持断言通过；三阶段画面人工核对和像素掩码检查通过，原始/恢复交并比为 1.0，两次不同译文的掩码交并比约 0.266。脚本已卸载，目标保持原文。

普通 TextImage Paint 观察仅命中动态列表，没有覆盖主菜单；面板调度入口观察才能找到主菜单按钮的真实文字 owner。实验也尝试在该回调退出前立刻恢复原文，内存设置通过但画面未出现译文，因此该临时切换方法不可作为修复。需要持续控件更新及可验证的生命周期恢复。

已验证 IVGui 句柄解析函数包含索引界限、序号及空闲项检查；候选原生实现需使用寿命校验处理隐蔽/销毁控件。仍需实现无样本固定布局的原生识别、刷新队列及停用确认；当前成功为控件刷新实机技术验证，尚非最新 App 自动刷新功能。

## 原生刷新接入结果

已实现 Panel 调度边界、标准 Label / TextImage 关联、UI 线程刷新、代次合并与停用恢复；不使用样本配置。原文来自保留的本地化索引；已有译文只按同一原文的实际返回记录认领，不做全局反向字典。句柄复用、外部改字、隐藏恢复与停用超时已有合成合同。输出错误、超长或新译文被拒绝时恢复原文，避免保留上一代译文。

原生 ABI 宿主同一按钮两代与恢复的内存和四帧像素断言通过；生产 Backend/Runtime 同菜单发布合同连续两次通过，三阶段画面人工确认。生产截图有桌面遮挡，完整生产四帧像素检查未作为通过项。后续应在无遮挡的独立 GUI 测试环境补齐，不靠放宽阈值通过。原始截图均本地保存。

未知编译形态保留原查询能力；标准短标签成功不能外推格式化、非本地化或非标准控件。最新主路径 Release App/Bundle 已经生产加载器验证，最后的拒绝输出回退修正已经定向测试并同步重建 App；用户换入新工件时需正常重启一次此前有驻留组件的目标。
