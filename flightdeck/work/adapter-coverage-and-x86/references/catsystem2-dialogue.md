# CatSystem2 对话入口调查

状态：本页记录前期完整正文捕获调查。后续原生实验适配器已实现并加入最新 App，合成验证通过；实机翻译验收等待旧 Runtime 所在目标正常重启。当前执行状态见 [原生 Slice](../slices/catsystem2-native.md)。

## 请求与基线

用户确认 VGUI 可用但未完全验收，要求先提交现有工作，再检查已启动的 NEKOPARA Vol. 3 当前对话。既有工作提交为 `7c7b986`，活动包回归 509 项通过、0 失败、25 忽略。系统菜单已经可用，菜单条目不能作为正文覆盖证据。

当前画面与现有 App 探针快照对照，64 条采集记录不含完整台词；正文断言明确失败。快照有丢弃计数，但没有证据将正文缺失归因于丢弃。静止画面没有正文系统绘字调用；切换文字时也未在被观察的 GDI 文字 API 或编码转换调用中获得完整正文。

目标目录的引擎配置组件及资源格式指向 CatSystem2；[CatSceneEditor 作者](https://github.com/marcussacana/CatSceneEditor)也将 Vol. 3 列为测试对象。不能将其他卷的引擎判断套用于本卷。

## 实际取得的入口

调查了 [LunaHook 的 CatSystem 实现](https://github.com/HIllya51/LunaTranslator/blob/main/src/NativeImpl/LunaHook/LunaHook/engine32/CatSystem.cpp)作为入口假设来源。其旧式通用字符串调用候选在当前样本指向大量非正文运行值，新式文字布局模式不匹配。未照搬其实现、编码修补或原地字符串覆盖方式，也未加入产品。

独立检查目标运行代码，找到内联命令名和处理函数组成的表。由 `str`、`apend` 命令处理函数的数据流追到文字对象方法：接收对象随调用传入，首个栈参数为完整 UTF-8 字符串。局部发现器从表项和反汇编推导观测入口，确认轮次不使用预填的样本函数地址；当前识别规则仍依赖一个编译形态，不能视为通用 ABI。

打开对话记录时，设置路径收到历史台词；关闭记录回到正文时，追加路径收到当前完整台词。两轮返回正文均捕获到两个正文对象的完整输入，按追加路径区分后，两轮对象一致。历史设置路径同时取得最初画面的完整台词。回调字符串与对应画面人工核对，精确字符串断言通过。没有通过逐字拼接、OCR 或全内存匹配生成捕获结果。

早期后台鼠标消息被游戏解释为推进一条对话，已向用户说明；随后改用确认前台窗口的输入，验证结束时关闭记录并停留在正文。初始台词的证据来自其后打开的历史记录，不能误记为初始静止画面即时回调。没有修改存档、安装资源或台词内容；有界观察器已卸载并断开。

## 下一步约束

生产实现应使用 CatSystem2 框架入口，不按游戏名、当前台词或机器地址识别。识别必须验证命令表归属、可执行目标及参数数据流，歧义时回退；用合成宿主覆盖拒绝错误形态和调用合同。

设置与追加是不同语义，历史与正文是不同对象，不能仅按相同字符串合并其生命周期。替换必须确认引擎控制标记、输入是否被复制、长度限制、字形支持和对象销毁机制。字典更新及停用恢复需要目标线程上的可信重建方式，不能把人工开关对话记录当作已实现的自动刷新。

当前台词已缓存时，单纯监听未来调用不会自动枚举既存文字。正式适配器还需明确首次附加的捕获策略。Frida 仅用于本地诊断，原始日志、地址、截图和捕获文本均留在本地测试目录；不加入 Runtime Bundle。
