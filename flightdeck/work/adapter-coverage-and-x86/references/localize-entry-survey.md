# 本地化上层入口：调查与最小验证

## 本轮完成

用户已授权按社区调研方向推进。本轮进行公开接口核对、目标模块元数据/代码的只读核查，以及独立生命周期模型验证；没有安装新 Hook、调用目标表的修改/重载方法、重启游戏或继续扩展逐字绘制。

1. 样本及其调用模块声明 `VGUI_Localize005`；只读跟踪既有接口引用后，找到实际对象的虚表，其方法位于 VGUI 模块。先校验副本与已加载文件相同，再使用副本分析结果；本机值仅存于本地证据目录。
2. 目标中的查询链和转换方法布局与 Valve SDK 2013 的紧凑 005 接口不同。按名字直接复用该公开头文件的槽位会存在调用错函数的风险。当前没有把调查中看到的样本槽位/地址写进生产适配器。
3. AlliedModders 的其他分支提供 FindSafe、旧转换方法及多种 ConstructString 声明，可解释接口家族存在不同形态；这尚不等于对实际对象的完整 ABI 证明，还要核对继承、重载排列、调用约定和实际入口。不可直接以社区分支名称替代目标能力检查。[社区 localize 接口](https://github.com/alliedmodders/hl2sdk/blob/portal2/public/localize/ilocalize.h)、[SDK 2013 接口](https://github.com/ValveSoftware/source-sdk-2013/blob/master/src/public/tier1/ilocalize.h)
4. 新增 [独立生命周期模型](../../../../test-support/vgui-localize-lifecycle/README.md)，通过 `scripts/test-localize-lifecycle.ps1` 在 x86/x64 各运行 6 项检查，无失败。

## 验证结果的范围

| 已执行的模型检查 | 约束 |
| --- | --- |
| 晚启用 | 已拷贝到控件的文字不会随查询层启用而自动更新 |
| 名称/索引两个入口 | 仅覆盖 Find 会漏过直接按索引取词 |
| 译文换代 | 新查询可用新译文，旧控件需要再次 SetText；旧查询指针仍需有效 |
| 停用与恢复 | 后续查询返回原文，不等于旧控件副本已恢复；重建后才恢复 |
| 缺失 token、原始表 | 缺失保持缺失，原始表不被覆盖 |
| 初始化前生效 | 首次取词前启用能覆盖之后创建的控件 |

这些是根据公开调用模式搭建的**合成生命周期模型**，不是实际 VGUI 接口的 ABI 合同，也没有连接 Glyphshift 的原生宿主或证明游戏像素变化。模型中的结果保留列表不设生产级预算，只用于短命验证进程，不能直接搬进长驻适配器。

## 下一步及停止条件

先形成独立的原生只读查询接入，覆盖实际名称/索引入口，并明确格式化路径；只有验证的 ABI 才允许安装。不要调用编辑器用的 SetValueByIndex 或开发用 Reload 来尝试强制刷新。

首个实机目标应是 **Hook 就绪后新建的控件**，并同时记录查询与可见文本。这能区分入口问题和历史控件缓存问题；不再要求用户到主菜单后反复附加并把无变化归咎于字典。

生产接入还缺少：可信 ABI profile、返回缓冲所有权/容量与可写语义、UI 线程与对象生命周期，以及既有控件刷新或初始化前部署。当前桌面 Runtime 的本轮检索未找到暂停启动目标再恢复的现成入口，不能把普通重启后附加描述为已覆盖初始化。

未取得这些条件时保持实验状态。共用 Core 不回退，VGUI 字形重放继续冻结；本轮不提交、不更新正式 Bundle/Catalog。
