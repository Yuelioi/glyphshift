# 本地化查询层：单标签可见替换、更新与恢复

## 结论

**上层查询路径已在授权实机的一个设置标签上完成可见首代替换、第二代更新、停用后重建恢复。** 不需要重启游戏，本轮通过关闭并重新打开设置页完成控件重建。该结论仅覆盖本次标签、目标版本和新建界面，不表示所有主菜单或所有 Source 版本已支持。

实现是显式启用的 Frida 实验工具，尚未接入 Glyphshift 正式 Native Adapter、字典发布流程或 Runtime Bundle。此前的逐字重放仍冻结，不因本实验成功而晋级。

## 实施范围

- 复用上一轮确认的名称与索引查询入口；重新核对当前对象、方法所属模块、方法字节及调用约定。
- 只针对一个外部提供的 token 与完整原文匹配返回值，不在源码中写入目标词句或样本地址。
- 两代译文分别从控制端分配到目标进程的独立可写数据页；不覆盖原表、安装文件、函数参数或设置。
- 嵌套查询只在外层改写返回指针，避免名称查询内部调用索引查询时重复处理。
- 停用恢复后续查询，关闭并重开页面使控件取得原文。已有副本不是靠解除 Hook 自动恢复。

工具及命令见 [探针说明](../../../../test-support/vgui-localize-probe/README.md)。

## 验证

独立 MSVC x86 宿主实际附加验证了名称/索引两条路径、两代文字、旧控件副本、重建恢复、原始表不变、旧指针在脚本卸载后有效、调用者改写缓冲后的禁用，以及过期代次/分配上限拒绝。

早期清理顺序中，代理断开与合成宿主立即退出交叠时出现过退出超时。失败记录保留；清理改为先停止观察并卸载脚本、验证旧指针、正常结束自身宿主、最后释放会话，连续三轮正常退出。不能据此推导第三方工具在所有退出场景都可靠。

实机单轮结果：

| 阶段 | 查询/控制证据 | 画面证据 |
| --- | --- | --- |
| 首代 | 指定代次两次替换命中 | 标签显示首代测试文字 |
| 次代 | 发布新代次并重建后，两次替换命中 | 同一标签显示第二代测试文字 |
| 停用 | enabled=false；重建后替换计数不再增加 | 标签恢复原文 |
| 收尾 | 停止确认 id 匹配、最终状态关闭、观察脚本无错误输出 | 已取消设置页回到主菜单，目标正常响应 |

三个阶段截图均检查了实际显示文字。另以同尺寸截图的固定标签区域提取高亮中性色文字掩码作机器断言：原始/恢复掩码交并比约 0.975，首代/次代约 0.632，原始/首代约 0.208，分别满足恢复相似与两代有差异的条件。该像素检查不是 OCR，文字内容仍以截图人工核对为准；没有使用归档 UIA/OCR。

本地自动化脚本最后曾先判断“观察进程已退出”，再读取已经写出的停止确认，造成收尾误报。已纠正判断顺序，并对本轮实际确认、最终状态、错误日志与像素结果重新执行断言；没有为这个收尾判断重复修改游戏文字。

## 仍需产品化处理

1. 当前方法配置是经核对的单次实验输入，不是通用 ABI 自动识别；正式适配器须有可验证版本能力与拒绝路径。
2. 原函数返回可写指针，实验只验证普通读取/复制者及一个改写拒绝用例，不能宣称任意调用者、任意线程兼容。
3. 每次会话最多分配 16 页，旧返回页保留至目标退出。本轮实际使用两页；这是有界实验的生命周期取舍，不是长期会话回收方案。
4. 格式化文本、未走本地化查询的文本、历史控件自动刷新、主菜单初始化覆盖仍未验收。
5. 正式实现应接入已有 Core/字典代次和 Native Host，再按相同三阶段验证；不把 Frida 或测试词句作为产品依赖/预设。

原始 token、译文、截图、对象地址、控制文件和失败日志全部留在本地测试目录。未提交本轮改动，未更新正式 App。
